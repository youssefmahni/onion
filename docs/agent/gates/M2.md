## What was built (M2)

- Fake DeepSeek server (stdlib) with healthy / rate_limited / truncating / slow_under_load scenarios and request recording without Authorization values.
- `depot_llm`: libcurl-multi client on `curl_multi_poll`, stable heap ownership, HTTP/2 preference with HTTP/1.1 fallback, CPU reply-parsing pool, integer-decimal budget with reservations, timeout-as-uncertain-spend, adaptive limiter with hourly probe baseline, circuit breaker per decision 0006, separate connect timeout (decision 0007), FD ceiling.
- Developer CLI: `llm bench` (capacity, reuse, half-budget, adaptive), `llm limiter-trace --csv`, `llm models`, `llm probe`.
- Tests: limiter, budget, metering, breaker unit tests; closed-port / reset / timeout / 401 / 402 / truncation / 400 regressions; fake-server smoke and 1,000-concurrency load tests; trace contract tests.
- Evidence: trace CSVs, benchmark set, real probe (all under `docs/agent/evidence/m2/`).

## Decisions made

- 0007 connect timeout (Accepted); 0002 update (curl pin + G6); 0004 update (live validation findings).

## Deviations from DESIGN.md

- `Client::Options.connect_timeout_s` is a new client option mandated by the owner's brief §3.3 (decision 0007). `DESIGN.md` node.conf lists `llm.timeout_s` only; the connect timeout is a client-side default (10 s), surfaced through the CLI, and does not change any DESIGN.md constant.

## Known issues and risks

- DeepSeek's automatic prompt cache did not engage for a 17-token repeated prefix (decision 0004). Cache-hit metering is implemented and will be observed in M3's real campaign with long fixed instruction text.
- Hosted CI has no real fp64 GPU (M1 carry-over); the Mac Pro runner remains an owner action (OA-3).
