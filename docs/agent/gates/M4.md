## What was built

- Device keys (Monocypher Ed25519, seed convention cross-checked against the M1 golden signature), `device_id`, the 20-bit slot, the key-store flow on first `node run`, and slot-scoped 64-bit TK ids (`TK%05lld`, slot × 2^40 + counter) wired into the engine.
- The `Ed25519Signer` replacing the `NullSigner`; batch 1 chains from the public-key hash.
- Batch verification with every rejection case (bad signature, bad prev, bad hash, gap, non-member, past cutoff, unknown version) — quarantined, never applied.
- Segments sealed at 64 MB with zstd and replayed across restarts; the verified torn-tail repair cuts the tail on replay.
- Checkpoints: `VACUUM INTO`, signed manifests with the version vector and the Merkle root (decision 0009), kept to the last 3, written every 6 h or 100,000 applied records.
- `data_depot admin keygen --out <path>`: prints the public key, refuses paths inside the data directory.
- `data_depot genesis-import`: the signed one-time corpus import with a duplicate-path proposal/resolution gate, legacy settles/atomics, and a verifier (per-layer counts, parents present, Merkle root against a fresh CSV read).
- `docs/CUTOVER.md` (freeze, import, verify, switch, rollback) and `tools/import/weekly_dry_run.sh`.
