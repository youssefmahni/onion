# Data Model — Onion Knowledge Engine

## 1. The 10-level "Onion" hierarchy

The knowledge base is a strict 10-level tree. Every node's identity is its **path** (never its title), so renames never break links.

| Layer | File | Node type | Meaning |
|---|---|---|---|
| L0 | `Onion - level_00.csv` | **Phase** | `P01`..`P09` (Initiation … Operations) |
| L1 | `Onion - level_01.csv` | **Artifact** | Inputs (`IN…`, green in UI) / outputs (`OUT…`, amber), interleaved |
| L2 | `Onion - level_02.csv` | **Task** | Work task (`T01`…) |
| L3 | `Onion - level_03.csv` | **Sub-task** | Sequenced step (`ST01`…) |
| L4 | `Onion - level_04.csv` | **Task Detail (TD)** | Verb-level activity (`TD1362`) |
| L5 | `Onion - level_05.csv` | **Item** | Work item; 50–500 per TD (`TK…`) |
| L6 | `Onion - level_06.csv` | **Sub-item** | Items self-nest from L5 down |
| L7–L9 | `level_07..09.csv` | **Deeper** | Wired but reserved; **hard cap L9** (a 10-segment path never expands) |

## 2. CSV formats

- **L0:** `ID,Phase` — e.g. `P01,Initiation`
- **L1:** `ID,ID-L1,DOC` — e.g. `IN03,P01-IN03,Customer Needs`
- **L2:** `ID,ID-L2,Tasks & Activities`
- **L3+:** `ID,ID-L<N>,Title` (L3 header literally `Title`)

Notes:
- Columns are **path-relative**: each level stores its own id and the full parent path (`ID-L<N>`).
- Writes quote fields containing `,"\n`; a minimal splitter honours `""` escapes.
- Level files are **append-only** during funnel runs (crash-safe per node); `rebuild_json.py` reads all 10 to regenerate `Onion.json`.

## 3. ID & path scheme

- IDs are uppercase; `TK` ids are zero-padded to 5 (`TK%05d`), `TD` ids are not padded.
- Path = `parent-path + "-" + own-id`, e.g.
  `P01-IN01-T03-ST47-TD1362-TK15001-TK16400`
- `depot_core::td_prefix(path)` cuts a path at the 5th `-` (the TD boundary).
- `tk_next` = max `-TK<n>` suffix across **all** level files + 1; it is an atomic counter inside `run_funnel` (allocated under the mutex — zero duplicates). (`depot_core::next_tk`, the ingest helper, scans L5+L6 only; the funnel scans everything.)
- **Never rename by title.** Identity is the path. The canonical-form self-reference guard prevents a node becoming its own child.

## 4. State / audit TSVs

### `funnel_state.tsv` — resume ledger (append-only, never rewritten)
```
path \t kept \t atomic \t retries \t score \t unix_ts
```
A node is "done" (skipped by re-runs) iff its path appears here. Only the successful/final pass is recorded — one row per settled pass (a `--force` re-expansion appends a fresh row for the same path).

### `funnel_critique.tsv` — critique audit
```
path \t score \t issues \t remove;remove;… \t add;add;…
```
Semicolon-joined lists, TSV-sanitized.

### `atomic_items.tsv` — atomic leaf flags
```
path \t 1
```
Written only when a pass produced ≥1 atomic child. Folded into `Onion.json` as `atomic: true`.

### `node_llm_report.tsv` — llm-loop verdict audit (9 columns)
```
path \t layer \t title \t parent \t children \t valid \t fixed \t admits_children \t error
```
The llm loop's done-set is its first column; `--force` re-checks.

### Other runtime artifacts
- `expand_decisions.csv` — ingest expansion registry: `Title,Instances,Decision,SubItems,Source`; rows with `Decision=expand` provide pipe-separated sub-items (built once by a 16-subagent classification of 5,739 titles → 18.6k L6 rows).
- `title_aliases.tsv` — ingest merge audit (`depot-form \t incoming \t auto-merge|spelling-normalized`).
- `llm_pending_expansion.txt` — nodes judged `admits_children=true` but childless (deduped on append).
- `node_tools.tsv` — **planned** tools step output (`path \t tool1|tool2|…`); no producer exists in the code yet — not merged into `Onion.json`.

## 5. `Onion.json` — canonical read artifact

Regenerated by `rebuild_json.py` (the controller runs it every ~60 s). Atomic write (`.tmp` + `os.replace`), compact form.

```json
{
  "name": "OmniCommerce Onion",
  "description": "…",
  "generated": "<UTC>",
  "summary": {
    "total_nodes": 316234,   # example from the 2026-10 snapshot; grows with every funnel run
    "by_layer": {"L0": 9, "…": "…"},
    "funneled": "…", "kept_total": "…", "atomic_total": "…",
    "atomic_items": "…", "source_files": ["…"]
  },
  "levels": [{"file": "…", "columns": "…", "count": N}, "…"],
  "tree": {
    "P01": {"id": "P01", "path": "P01", "name": "…", "level": 0,
             "artifacts": {"IN01": {"tasks": {"T01": {"subtasks": {"ST01": {
               "details": {"TD1": {"items": {"TK…": {"items": {"…"}}}}
             }}}}}}},
    "…": "…"
  }
}
```

Each node: `id`, `path`, `name`, `level`, `children` (count); where processed: `funnel {kept, atomic, retries, score, ts}`, `critique {score, issues, remove[], add[]}`; where flagged: `atomic: true`.

## 6. Ingest merge semantics (lexical trust)

- `canonical(title)` → lowercase, filler-word-stripped, singularized, sorted key form.
- Similarity (`sim_keys` = max of LCS-ratio and Jaccard-on-distinct-tokens):
  - `≥ 0.95` → skip (near-duplicate)
  - `≥ 0.85` → merge (keep depot form; audit in `title_aliases.tsv`)
  - `0.70 – 0.85` → candidate (style gates decide)
  - else → new node
- Style gates (`style_flags`): title-case enforcement, no questions, no emoji, length bounds.

## 7. Integrity invariants (never violate)

1. Zero duplicate TK/TD ids.
2. Zero orphan nodes (every child's parent exists).
3. 50–500 L5 items per TD.
4. A node can never be its own descendant.
5. `funnel_state.tsv` rows are append-only — never rewrite or prune historical rows except deliberate cleanup of API-failure rows.
