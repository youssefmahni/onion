STEP 1 · INGEST LOOP

Research comes in

Feed the depot a TSV of task → item → sub-items. Every entry is canonicalized and checked with lexical trust: duplicates are skipped, near-duplicates auto-merged or renamed to the depot spelling, and new items are style-gated before they land.

STEP 2 · VALIDATE LOOP

Every node is checked

A root-to-leaf sweep walks L0 → L9. One stateless LLM call per node answers: is this title good? does this node have children? Bad titles are fixed, and the verdicts are recorded so the next run only checks what's new.

STEP 3 · FUNNEL LOOP — four agents

A node is grown top-down

For one node, the pipeline runs four agents in order. This is the heart of the workflow:

AGENT 1 · PLANNER

Break it into aspects

Plans 4–8 dimensions of the node — the roadmap for coverage. On a retry pass it receives the previous critique, so the next round deliberately fills the gap.

AGENT 2 · WORKERS (parallel)

Draft the top 500

One call per aspect, running in parallel — each drafts top-100 candidates. Merged and deduped into a pool of up to 500, then narrowed: keep the best 400, then the best 300.

AGENT 3 · CRITIQUE

Score and flag

Grades the pool 0–1: hallucinations, duplicates, vague items, missing categories. Its "add" list is the self-correction signal, and its score decides whether the node gets a retry.

AGENT 4 · SYNTHESIZER

Pick the final set

Merges candidates + critique into the balanced final set (3–100, it decides). Each item is stamped atomic — the simplest item possible — or nest further.

STEP 4 · NEST DOWN

Write, then loop again

New children are written to the CSVs immediately (crash-safe). Non-atomic children go back into the queue, and the funnel runs them one layer deeper — L5 → L6 → L7… — until every leaf is atomic.

The loop, looping: 500 → 400 → 300 → best set → non-atomic children re-queue → the next loop fixes what the last one missed. Critique score < 0.7 or a failed API call re-queues the node once with its issues injected.
STEP 5 · SUPERVISE & CONTINUE

A machine-aware supervisor runs it

The controller samples CPU / RAM / NIC / GPU and live-resizes the worker pool — more threads when idle, fewer when you're busy. Everything is resumable: state, critique audit, live dashboard (WASM + WebGL) on :8080.
